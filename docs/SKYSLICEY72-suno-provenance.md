# SKySLICEY72 — Suno provenance boundary

**Status:** preservation research note · NO ACQUISITION SCOPE CHANGE  
**Priority guard:** the September 3 preservation deadline does not widen browser/network/session authority.

## Why this belongs in the Vault

SKySLICEY72 suggests that creative generation history may contain distinctions richer than final audio bytes:

```text
source relation
-> generation occurrence
-> sibling candidates
-> later branch choices
-> possible recombination
```

The Vault's job is not to infer that history. Its job is to preserve honest source evidence when such evidence is actually available through already-lawful surfaces.

## Hard law

> **A WAV CANNOT PROVE ITS BRAID.**

Audio bytes may be identical, similar, or divergent without exposing:

- whether two tracks were siblings in one generation occurrence;
- which candidate was selected first;
- which later derivative used which ancestor;
- any handedness/orientation relation imagined by a research decoder.

Therefore:

```text
audio similarity != generation ancestry
filename proximity != sibling relation
UI adjacency != durable provenance unless witnessed and attributed
inferred braid != receipt
```

## Honest preservation target

If a lawful witnessed surface supplies generation-level identifiers or sibling grouping, preserve them as provenance payload/ref data without promoting them to artistic meaning.

Candidate future metadata questions:

```text
provider generation occurrence id available?
sibling output relation explicitly witnessed?
parent / remix / extend relation explicitly witnessed?
observed-at timestamp?
source surface / witness receipt?
```

If unavailable:

```text
omit / unknown
```

never fabricate.

## Relationship to SKySLICEY72

The research stack proposes:

```text
phase position × local orientation × crossing history
```

as a useful model for some creative formation histories.

The Vault preserves only the source facts that might later allow another system to build such a model. It does not store `D3`, braid generators, or crossing signs unless an upstream declared workflow explicitly produces those as project-owned annotations.

## Candidate provenance separation

Keep these layers distinct:

```text
PROVIDER FACT
  witnessed identifier / relation from Suno surface

VAULT RECEIPT
  what was observed, downloaded, hashed, admitted, and when

PROJECT ANNOTATION
  later interpretation such as sibling, branch, orientation, or braid model
```

A project annotation may cite the Vault receipt. It may not rewrite it.
